# Plantilla de matriz de conformidad

**Estado:** plantilla

Esta matriz demuestra implementación, no selección. La selección exhaustiva vive en el registro de adopción. Cada requisito verificable de estándares adoptados debe aparecer aquí con trazabilidad.

| ID conformidad | ID STD/TOP | Estándar / versión | Requisito verificable | Aplicabilidad | Control implementado | Prueba/evidencia | Responsable | Resultado | Excepción / vencimiento |

|---|---|---|---|---|---|---|---|---|---|

| CON-001 | [STD-### / TOP-X-###] | | | Aplica / Condicional / No aplica | | | | Pendiente / Conforme / No conforme / No verificado | |

## Reglas de uso

- Una fila por requisito verificable o conjunto pequeño de requisitos inseparables.

- El ID STD IDs o TOP IDs debe existir en el inventario fijado por el proyecto.

- No marcar conforme por tener documentación: enlazar evidencia de implementación y prueba reproducible.

- Los requisitos condicionales indican disparador y evidencia de activación/no activación.

- Los no aplicables deben tener justificación en el registro; no crear conformidad ficticia.

- Las excepciones enlazan aprobación, mitigaciones, responsable y expiración.

- Resultados: Pendiente, Conforme, No conforme, No verificado, No aplica justificado. No verificado nunca equivale a conforme.

- Versionar la matriz y revisarla en diseño, CI, preproducción y operación según criticidad.
